# 17.3 Layout System

---

# 17.3.1 Purpose

The Layout System defines the visual and structural framework of the LexisGraph frontend. It specifies how pages share common user interface elements such as navigation bars, sidebars, headers, footers, dialogs, and content containers while leveraging the Next.js App Router's nested layouts.

A consistent layout system improves usability, reduces code duplication, and provides a uniform experience across the application.

---

# 17.3.2 Objectives

The Layout System shall:

- Provide consistent page layouts.
- Support nested layouts.
- Minimize duplicated UI.
- Improve navigation consistency.
- Support responsive design.
- Enable role-specific layouts.
- Support loading and error boundaries.
- Improve maintainability.

---

# 17.3.3 Design Principles

The layout system shall follow:

- Reusable layouts.
- Minimal page-specific UI.
- Shared navigation.
- Responsive containers.
- Accessibility-first design.
- Mobile-first development.
- Separation of layout and business logic.

---

# 17.3.4 Layout Hierarchy

The frontend shall use the following hierarchy:

```
Root Layout

↓

Authentication Layout

↓

Application Layout

↓

Feature Layout

↓

Page Layout

↓

Components
```

Each level shall have a clearly defined responsibility.

---

# 17.3.5 Root Layout

File:

```
app/layout.tsx
```

Responsibilities:

- HTML document.
- Global metadata.
- Theme Provider.
- Query Provider.
- Authentication Provider.
- Notification Provider.
- Global CSS.
- Fonts.

The Root Layout shall remain mounted throughout the application lifecycle.

---

# 17.3.6 Authentication Layout

Applies to:

```
/login

/register

/forgot-password

/reset-password
```

Structure

```
+-----------------------------+
|        Brand Logo           |
|                             |
|      Authentication Form    |
|                             |
|     Footer Information      |
+-----------------------------+
```

Authentication pages shall not display the application sidebar.

---

# 17.3.7 Application Layout

Used after successful login.

Structure

```
+------------------------------------------------+
| Header                                         |
+-------------+----------------------------------+
| Sidebar     |                                  |
|             |                                  |
|             | Main Content                     |
|             |                                  |
|             |                                  |
+-------------+----------------------------------+
```

Components

- Header
- Sidebar
- Breadcrumb
- Content Area
- Toast Notifications

---

# 17.3.8 Header Layout

The header shall contain:

- Organization Name
- Search Bar (Future)
- Notifications
- Theme Switch
- User Avatar
- User Menu

The header shall remain fixed while scrolling.

---

# 17.3.9 Sidebar Layout

Sidebar navigation shall include:

```
Dashboard

Policies

Compliance Reports

Analysis

Organization

Settings

Administration (Role Based)
```

The sidebar shall:

- Collapse on mobile.
- Support nested menus.
- Highlight the active route.
- Remember collapse state.

---

# 17.3.10 Content Area

The content area shall:

- Display page content.
- Support scrolling.
- Respect layout padding.
- Maintain consistent spacing.

Maximum width shall be configurable.

# 17.3.18 Modal Layer

The application shall provide:

- Confirmation Dialog
- Upload Dialog
- Delete Confirmation
- Report Preview
- User Invitation
- Organization Settings

Modals shall use a centralized dialog system.

---

# 17.3.19 Loading Layout

Every feature shall provide loading placeholders.

Examples

- Skeleton Cards
- Skeleton Tables
- Skeleton Reports
- Skeleton Charts

Loading UI shall closely resemble final content.

---

# 17.3.20 Error Layout

Error layouts shall support:

```
404

403

500

Offline

Maintenance
```

Each error page shall provide recovery actions.

---

# 17.3.21 Empty States

Empty states shall display:

- Illustration
- Message
- Primary Action

Examples

"No policies uploaded."

"Generate your first compliance report."

---

# 17.3.22 Notifications

Toast notifications shall appear in the upper-right corner.

Supported types

- Success
- Error
- Warning
- Information

Notifications shall dismiss automatically unless user interaction is required.

---

# 17.3.23 Theme Support

The layout system shall support:

```
Light Theme

Dark Theme

System Theme
```

Theme selection shall persist across sessions.

---

# 17.3.24 Accessibility

Layouts shall:

- Support keyboard navigation.
- Maintain visible focus indicators.
- Use semantic landmarks.
- Support screen readers.
- Ensure sufficient color contrast.

---

# 17.3.25 Performance

The layout system shall:

- Keep shared layouts mounted.
- Avoid unnecessary re-renders.
- Lazy load heavy components.
- Optimize icons and images.
- Minimize layout shifts.

---

# 17.3.26 Security

Layouts shall:

- Hide unauthorized navigation items.
- Never expose restricted pages.
- Display organization-specific branding only after authentication.
- Protect administrative interfaces.

---

# 17.3.27 Best Practices

Developers shall:

- Keep layouts presentation-focused.
- Avoid business logic inside layouts.
- Reuse layout components.
- Maintain consistent spacing.
- Follow responsive design principles.
- Keep navigation synchronized with routing.

---

# 17.3.28 Acceptance Criteria

The Layout System shall be considered complete when:

✓ Shared layouts are reusable.

✓ Authentication pages use a separate layout.

✓ Application pages share common navigation.

✓ Responsive layouts function correctly.

✓ Loading and error layouts are implemented.

✓ Accessibility requirements are satisfied.

✓ Layouts remain performant.

---

# 17.3.29 Summary

The Layout System establishes the shared visual structure of the LexisGraph frontend by defining reusable layouts, navigation components, responsive containers, and accessibility standards. Through Next.js nested layouts and modular UI composition, it provides a consistent, scalable, and maintainable user experience while minimizing duplication and supporting future application growth.
