# Roles & Permissions

Version: 1.0

Last Updated: August 2026

---

# Purpose

This document defines the Role-Based Access Control (RBAC) model used throughout the LexisGraph platform.

It specifies:

- User roles
- Permissions
- Resource ownership
- Access rules
- Future enterprise extensions

The goal is to provide secure, predictable, and scalable authorization across all workspaces.

---

# RBAC Model

LexisGraph uses Role-Based Access Control (RBAC).

Every user belongs to:

Tenant
→ Workspace
→ Role

Permissions are granted through roles rather than individual users.

---

# Current Roles

LexisGraph currently supports four workspace roles.

```
Workspace Admin

Legal Analyst

Reviewer

Viewer
```

Future enterprise roles are documented later.

---

# Workspace Admin

## Description

The Workspace Admin has full control over the workspace.

Typical users

- Founder
- Head of Legal
- Compliance Manager
- General Counsel

---

## Responsibilities

- Configure workspace
- Invite users
- Manage permissions
- Create projects
- Upload documents
- Run analyses
- Review reports
- Manage billing
- Monitor compliance

---

## Access Level

Full Access

---

# Legal Analyst

## Description

Responsible for preparing compliance analyses.

Typical users

- Legal Associate
- Compliance Executive
- HR Compliance Officer

---

## Responsibilities

- Upload documents
- Upload regulations
- Create projects
- Run AI analysis
- Review findings
- Ask AI Assistant

---

## Access Level

Operational Access

---

# Reviewer

## Description

Reviews AI-generated reports before approval.

Typical users

- Senior Legal Counsel
- External Auditor
- Compliance Lead

---

## Responsibilities

- Review findings
- Approve reports
- Reject reports
- Add comments
- Export reports

---

## Access Level

Review Access

---

# Viewer

## Description

Read-only workspace member.

Typical users

- CEO
- Board Member
- Department Head

---

## Responsibilities

- Monitor compliance
- View dashboards
- Download reports

---

## Access Level

Read Only

# Security Principles

LexisGraph follows these principles.

## Least Privilege

Users receive only the permissions required for their role.

---

## Workspace Isolation

Users cannot access another workspace.

---

## Project Isolation

Projects remain independent.

Documents

Reports

Knowledge Graphs

Analyses

belong only to one project.

---

## Auditability

Every important action should be logged.

Examples

- Document upload
- Analysis started
- Report approved
- User invited
- Permission changed

# Summary

LexisGraph uses a workspace-scoped RBAC model that balances collaboration with security. Workspace Admins manage the platform, Legal Analysts perform operational compliance work, Reviewers validate AI-generated findings, and Viewers monitor compliance outcomes. This model is designed to scale from a single startup to large enterprises and law firms managing multiple client workspaces.
