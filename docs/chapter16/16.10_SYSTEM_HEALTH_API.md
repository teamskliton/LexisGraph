# 16.10 System & Health API

---

# 16.10.1 Purpose

The System & Health API provides operational endpoints for monitoring the health, readiness, liveness, performance, and version information of the LexisGraph platform. These endpoints are intended for infrastructure, monitoring systems, orchestration platforms, and administrators.

The API shall not expose confidential business data.

---

# 16.10.2 Objectives

The System API shall:

- Report application health.
- Verify service readiness.
- Verify application liveness.
- Expose platform metrics.
- Provide version information.
- Support monitoring systems.
- Support Kubernetes health checks.
- Support automated alerting.

---

# 16.10.5 Endpoints

## Health Check

```
GET /system/health
```

Returns the overall health of the platform.

Example Response

```json
{
    "status": "HEALTHY",
    "timestamp": "2026-07-20T12:00:00Z"
}
```

---

## Readiness Probe

```
GET /system/ready
```

Determines whether the application is ready to receive requests.

Checks:

- PostgreSQL
- Redis
- Neo4j
- Qdrant
- Object Storage

Returns

```
READY

NOT_READY
```

---

## Liveness Probe

```
GET /system/live
```

Determines whether the application process is alive.

This endpoint shall not verify external dependencies.

---

## Dependency Status

```
GET /system/dependencies
```

Returns the status of all dependent services.

Example

```json
{
    "postgresql": "UP",
    "neo4j": "UP",
    "qdrant": "UP",
    "redis": "UP",
    "object_storage": "UP",
    "llm_provider": "UP"
}
```

---

## System Metrics

```
GET /system/metrics
```

Provides operational metrics.

Example

```json
{
    "cpu_usage": 34,
    "memory_usage": 58,
    "active_jobs": 12,
    "queue_size": 4
}
```

This endpoint may integrate with Prometheus.

---

## Platform Information

```
GET /system/info
```

Returns:

```json
{
    "application": "LexisGraph",
    "version": "1.0.0",
    "environment": "production"
}
```

Sensitive configuration shall not be exposed.

---

## API Version

```
GET /system/version
```

Returns API version information.

Example

```json
{
    "api_version": "v1",
    "application_version": "1.0.0"
}
```

# 16.10.6 Health Status

Supported health states:

```
HEALTHY

DEGRADED

UNHEALTHY

STARTING

STOPPING
```

The platform shall continue operating in a degraded state where possible.

---

# 16.10.7 Readiness Checks

Readiness shall verify:

- Database connectivity
- Neo4j availability
- Qdrant availability
- Redis availability
- Object Storage connectivity
- Background worker availability

If any critical dependency is unavailable, the readiness probe shall fail.

---

# 16.10.8 Liveness Checks

Liveness shall verify only:

- Application process
- Internal runtime

External services shall not affect liveness.

---

# 16.10.9 Metrics

Operational metrics may include:

```
CPU Usage

Memory Usage

Disk Usage

Queue Length

Average API Latency

Active Users

Running Jobs

Background Workers

AI Requests

Token Usage
```

Metrics shall be suitable for monitoring dashboards.

# 16.10.12 Audit Events

The platform shall record:

- System Restart
- Service Failure
- Dependency Failure
- Recovery Event
- Metrics Access
- Administrative Health Check

Operational events shall support incident investigations.

---

# 16.10.13 Security

The System API shall:

- Limit public information.
- Hide infrastructure details.
- Restrict sensitive metrics.
- Protect monitoring endpoints.
- Prevent information disclosure.
- Require authentication for administrative diagnostics.

---

- OpenTelemetry
- Loki (Logs)
- Alertmanager

Future monitoring integrations may be added.

# 16.10.16 Acceptance Criteria

The System API shall be considered complete when:

✓ Health endpoints are operational.

✓ Readiness and liveness probes function correctly.

✓ Dependency status is available.

✓ Operational metrics are exposed.

✓ Platform version information is accessible.

✓ Monitoring integrations are supported.

✓ Sensitive information is protected.

---

# 16.10.17 Summary

The System & Health API provides operational visibility into the LexisGraph platform by exposing health, readiness, liveness, dependency status, metrics, and version information. It enables reliable deployment, proactive monitoring, and rapid incident response while ensuring that sensitive infrastructure details remain protected.
